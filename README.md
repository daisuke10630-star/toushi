# 日本株テクニカル分析ダッシュボード

グランビルの法則・パーフェクトオーダー・ボリンジャーバンド・RSI・ローソク足パターン（陽線/陰線/大陽線/大陰線/ダブルトップ/ダブルボトム）に基づき、
ウォッチリスト銘柄を自動判定し、買い目・売り目・損切りライン・利確ラインを提示するダッシュボードです。

**重要な前提（必ず読んでください）**
- このアプリは**投資助言ではありません**。最終判断はご自身で行ってください。
- **リアルタイム性の限界**：既定の取得元（yfinance）はザラ場中でおおむね15〜20分遅延です。秒単位の板情報は取得できません。

---

## ★（星）が意味すること／意味しないこと

**★は「上昇確率」ではありません。**

★は `signals.py` のルール（パーフェクトオーダー成立で+2、RSI過熱で-1 など）で
強気側の条件がいくつ揃ったかを加減点しただけの、**条件の揃い具合**です。
実際の値動きと突き合わせた検証は含まれていません。

★4の銘柄は「チェックリストの項目が強気側に多く揃っている銘柄」であって、
「上がりやすい銘柄」ではありません。実際の成績は次の「AI信頼度」で確認してください。

## AI信頼度とは（＝バックテスト勝率）

**AI・機械学習は一切使っていません。** 項目名はご要望に合わせていますが、
中身は `backtest.py` による素朴な売買シミュレーションの実測勝率です。

| 項目 | 内容 |
|---|---|
| 何を測っているか | この銘柄の過去データで、同じ★水準のシグナルが出たとき、提示した損切り・利確ルール通りに売買していたら何%成功したか |
| 先読み対策 | 各時点で「その時点までのデータ」だけを渡してシグナルを再計算（MA・RSI・BBはすべて後ろ向きのrolling計算） |
| 約定の判定 | シグナル発生後、検証期間内にエントリー目安（MA1）まで押したら約定とみなす |
| 勝敗の判定 | 損切りラインと利確目標①のどちらに先に触れたかで決定 |
| 保守的にしている点 | 同じ足で両方に触れた場合は損切り扱い。押し目を付けずに上昇した分は「未約定」で勝ちに数えない |
| 売買コスト | 往復0.1%（`TRADING_COST_PCT`）を各トレードから差し引き済み |
| 反映していない点 | 板の厚さ（提示価格で必ず約定する前提） |
| **対照実験** | 同じ期間を「シグナルなしで持つだけ」の成績と必ず併記。この差がプラスでなければシグナルに意味はない |

サンプル数が `BACKTEST_MIN_SAMPLES`（既定10回）未満の場合は「データ不足」と表示します。

**平均損益も併記しています。勝率が高くても平均損益がマイナスなら、そのルールは負けます。**

## 検証で到達した現在のルール

すべての判断は「シグナルを使わず単純に20日持つだけ」のベンチマークと比較して決めています。
**上昇相場では何を買っても勝つため、勝率や期待値の絶対値だけでは良し悪しを判断できません。**

### ⚠ 実際に資金を回すと、買い持ちに負けます

「1日あたりのリターン」ではベンチマークを上回りましたが、**その指標には穴がありました。**
ポジションを持っている日の効率しか見ておらず、**現金で待っている時間を無視**しています。

実際に資金を回したシミュレーション（3年・30銘柄・手数料込み）：

| 同時保有 | 建てた回数 | 年率 | 買い持ちとの差 |
|---|---|---|---|
| 1銘柄 | 152回 | +17.1% | -8.0% |
| 3銘柄 | 363回 | **+19.1%** | -6.1% |
| 5銘柄 | 475回 | +13.1% | -12.0% |
| 10銘柄 | 560回 | +8.1% | -17.0% |
| **同じ30銘柄を買い持ち** | — | **+25.1%** | — |

同時保有1銘柄だと、3年で152回 × 平均2.3日 = 約350日しか投資していません。
3年は約750営業日なので**半分以上は現金**です。その間も市場は上がり続けていたため、
**待機時間の機会損失が日々の優位性を食い潰しました。**

なお買い持ちの+25.1%は2023〜2026年の日本株が異常に強かった結果で、
この水準が続く前提で考えるのは危険です。逆に下落相場では現金比率の高い戦略が
有利に働く可能性がありますが、**それは今回の検証では確かめられていません。**

再現するには `scratchpad/portfolio.py` 相当の日付順シミュレーションが必要です
（`backtest.evaluate` の集計だけでは資金効率が測れません）。

### 現在の設定と、そこに至るまでの経緯

10年データ（コロナショック・2022年の下落を含む）・30銘柄・往復コスト0.1%込みで検証しています。

| 項目 | 設定 |
|---|---|
| エントリー | 直近20日高値を上抜けたら逆指値（順張り） |
| 損切り | ATR（14日平均値幅）× 2 |
| 利確① | 損切り幅 × 1.5（リスクリワード比 1:1.5） |
| 保有上限 | 3営業日（実際の平均保有 2.3日） |
| 追加情報 | 業種相対強弱のみ有効 |

ベンチマーク（同条件の単純保有）に対して **1日あたり 前半+0.118% / 後半+0.165%**。

**長期保有（15日・RR1:3）では優位性が出ませんでした**（1日あたり-0.03%/-0.40%）。
短期・近い利確に切り替え、評価軸を「1日あたりのリターン」にしたことで初めて
両期間でベンチマークを上回りました。

> **ベンチマークは戦略と同じ損切り条件・同じ保有期間で計算しています。** 条件が食い違ったまま
> 比較すると誤った結論になります（実際に一度、20日保有を「勝ち」と誤判定しました）。

### 唯一効いた追加情報：業種の相対強弱

テクニカル指標だけでは優位性が出なかったため、価格以外の情報を3つ追加して
10年・30銘柄で検証しました（★4/★5 × 前半/後半 の4通りで判定）。

| 追加した情報 | ★4 前半/後半 | ★5 前半/後半 | 通過 |
|---|---|---|---|
| なし（価格のみ） | +0.42% / **-0.03%** | +0.19% / **-0.47%** | 0/4 |
| 出来高急増 | +0.52% / **-0.06%** | +0.33% / **-0.05%** | 0/4 |
| 市場（TOPIX）相対強弱 | +0.43% / **-0.20%** | +0.25% / +0.13% | 1/4 |
| **業種相対強弱** | **+0.55% / +0.17%** | **+0.35% / +0.42%** | **4/4** |

**同業種の平均に対して強いかどうか**だけが、一貫してベンチマークを上回りました。
出来高急増は効果ゼロ、市場全体との比較もほぼ効きません。
「上がっている業種の中で、さらに強い銘柄か」という情報に意味があったことになります。

現在は業種相対強弱のみ有効です（`config.py` の `USE_SECTOR_STRENGTH`）。
出来高・市場相対強弱は計算だけ続けており、フラグ1つで復活できます。

> **注意：** 5通りの組み合わせ × 2つの★水準 = 10通りを比較しています。
> 偶然いくつか通過することは起こり得るため、これだけで確定とは言えません。
> 業種相対強弱が4/4で通ったのは偶然にしては良い成績ですが、決定的ではありません。

業種は yfinance から取得して `sector_cache.json` にキャッシュしています
（246銘柄中244銘柄で取得成功、11業種）。

### 決算日は警告のみ（★には影響させない）

yfinance から取れる決算日は直近数回分しかなく、**10年分の過去検証ができません。**
検証できないものを加減点に入れると★を歪めるため、決算は警告表示のみとしています。

決算発表はチャートの形に関係なく窓を開けるため、**損切りラインを飛び越えて
約定するリスク**があります。10営業日以内に決算がある場合に警告します。

### ★には優位性がありません

10年データで★の水準ごとにベンチマーク比を測った結果です。**★を上げても改善しません。**

| ★の水準 | 前半のベンチ比 | 後半のベンチ比 |
|---|---|---|
| ★3以上 | +0.04% | -0.05% |
| ★4以上 | +0.18% | -0.33% |
| ★5以上 | -0.16% | +0.09% |

符号がばらついており、ノイズと区別がつきません。
**★4の銘柄が★3より有望、という根拠はありません。**

### 最大の発見：エントリー方式が全てだった

旧版の「5日線への押し目を待つ」方式は、**価値を破壊していました。**

優位性は作れませんでしたが、**エントリー方式の変更だけは大きく効きました。**
10年データ（★4以上・利確RR1:3）での比較です。

| エントリー方式 | 前半の期待値 | 後半の期待値 | ベンチ比（後半） |
|---|---|---|---|
| 高値ブレイク（順張り・現行） | +0.76% | +0.83% | -0.40% |
| 翌日成行（待たない） | +0.67% | +0.94% | -0.29% |
| **押し目待ち（旧版）** | **-3.61%** | **-3.79%** | **-5.02%** |

**旧版の「5日線への押し目を待つ」方式は、1トレードあたり約4%を失っていました。**
勝率も22%しかありません（現行は50〜54%）。2394回/1100回という大きなサンプルで
一貫しており、これは本物の欠陥です。押し目を待つと下げている銘柄ばかり掴み、
上がっていく銘柄を取り逃がすためです。

つまり現在のルールは「勝てる」のではなく、**「大きく負けるのをやめた」**状態です。

### 保有期間は3日が最適（短期ほど良い）

**評価軸を「1トレードあたりの期待値」から「1日あたりのリターン」に変えました。**
資金は一度に1銘柄しか持てないため、同じ日数でより多く回転できるほうが有利です。
1トレードあたりで比べると、保有期間の長い設定が不当に有利に見えてしまいます。

保有3/5/7/10日 × 損切り5通り × 利確7通り = 140通りを総当たりした上位です。

| 保有上限 | 損切り | 利確 | 約定 | 勝率 | 平均保有 | 前半ベンチ比 | 後半ベンチ比 |
|---|---|---|---|---|---|---|---|
| **3日（採用）** | **ATR×2** | **RR1:1.5** | 562 | **55%** | 2.3日 | +0.118%/日 | **+0.165%/日** |
| 3日 | ATR×2 | RR1:2 | 562 | 55% | 2.3日 | +0.134%/日 | +0.155%/日 |
| 3日 | ATR×2 | 固定2% | 562 | **63%** | 1.8日 | +0.020%/日 | +0.061%/日 |
| 7日 | ATR×2 | RR1:1.5 | 804 | 54% | 4.4日 | +0.053%/日 | +0.064%/日 |
| 10日 | ATR×2 | RR1:1.5 | 894 | 53% | 5.7日 | +0.054%/日 | +0.034%/日 |

**上位8件すべてが保有3日**でした。短期化すると勝率も上がります（55〜63%。
従来の15日設定は50%前後）。利確を遠くすると取りこぼすというご指摘の通りでした。

損切りもATR×3からATR×2に変更しています（×3は保有15日前提の設定でした）。

より高い勝率を優先するなら「固定2%利確」で63%になります。
1日あたりのリターンは落ちますが、`config.py` で切り替えられます。

### 損切り・利確でわかったこと

- **損切りはATR×3が最良。** 固定8%も悪くありませんが、ATR連動のほうが上回りました。
  値動きの荒い銘柄ほど損切りを広く取る方式です。1〜3%に狭めると大きく悪化します。
- **利確は損切り幅の3倍（リスクリワード比 1:3）が最良。** 旧版の BB+2σ は銘柄・局面で
  現値との距離がバラバラで、損切り幅と釣り合いませんでした。

### このアプリの現実的な使いみち

シグナルとしての優位性はありません。それでも残る価値は次の2つです。

1. **明確に悪い型を排除できる。** 押し目待ちが-4%/回だと分かったのは実測の成果です。
2. **測定器として使える。** 思いついたルールを、必ず単純保有と比較しながら検証できます。
   「勝率が高い」「上昇相場で儲かった」に騙されない仕組みが入っています。

ダッシュボードの「AI信頼度」欄には**銘柄ごとの単純保有との差を常設**してあります。
必ずこの差を確認してください。全体で優位性がない以上、
**この差がプラスでない銘柄でシグナルに従う理由はありません。**

### 検証の限界

- 25銘柄・10年・数千トレードの規模です。母集団は日経225中心で、小型株は含みません。
- 手数料は往復0.1%と仮定しています。実際の条件によって結論は変わり得ます。
- 板の厚さ（提示価格で必ず約定するか）は考慮していません。
- **過去に優位性がなかったことは、将来もないことの証明ではありません。**
  同様に、過去に優位性があっても将来を保証しません。

### 分足を削除しました

5分足・1分足はどの損切り幅でも期待値が実質ゼロ（-0.00%〜-0.25%）で、手数料を引くと
マイナス確定だったため削除しました。分足では利確目標が現値から0.2〜1%しか離れず、
往復コスト0.05〜0.1%が利益の10〜50%を食う構造的な問題があります。
復活させる場合は `timeframes.py` に `TimeframeParams` を足すだけです。

## データ取得元

`backend/.env` の `DATA_SOURCE` で切り替えます。

| 値 | 取得元 | APIキー | データの鮮度 | 分足 |
|---|---|---|---|---|
| `yfinance`（既定） | Yahoo!ファイナンス | 不要 | 前営業日の終値まで | 対応（1分足=直近7日、5分足=直近60日） |
| `jquants` | J-Quants API V2（JPX公式） | 必要 | **無料プランは約12週間遅延** | 非対応（別売りアドオン） |

### J-Quants を使う場合の注意
- **V1は廃止されました**（HTTP 410 が返ります）。V2 はリフレッシュトークン方式ではなく、
  マイページで発行する **APIキー**（`x-api-key` ヘッダー）方式です。
- 無料プランの株価四本値は「12週間前 〜 2年12週間前」しか取得できず、直近の売買判断には使えません。

### 使えない取得元
- **株探（kabutan.jp）はスクレイピング不可**です。利用規約で自動取得が明示的に禁止されており、
  公開APIもなく、プログラムからのアクセスは HTTP 403 で遮断されます。

## 時間軸ごとのパラメータ

日足の MA 5/25/80/120 は「約1週間 / 1か月 / 4か月 / 半年」という*期間の意味*を持つ設定です。
これを1分足にそのまま当てると「5分 / 25分 / 80分 / 120分」になり、想定と噛み合いません。
東証の立会時間（前場150分＋後場180分＝330分）を基準に、同じ役割分担を再現しています。

| | 日足 | 5分足 | 1分足 |
|---|---|---|---|
| MA1〜MA4 | 5 / 25 / 80 / 120日 | 5 / 25 / 66 / 132本<br>(25分/2時間/1日/2日) | 5 / 25 / 75 / 200本<br>(5分/25分/75分/200分) |
| RSI 期間 | 9 / 14 | 9 / 14 | 14 / 28 |
| RSI しきい値 | 70 / 30 | 75 / 25 | 80 / 20 |
| BB 期間 | 25 | 25 | 25 |
| 検証期間 | 20営業日 | 12本(1時間) | 30本(30分) |

RSI は時間軸が短いほど頻繁に振り切れるため、期間を延ばしつつしきい値も外側に広げています。

**これらは慣習的な設定を上記の考え方で整えたもので、最適化も統計的検証もしていません。**
すべて `backend/app/timeframes.py` で変更できます。

## セットアップ

### 1. バックエンド起動
```bash
cd backend
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
uvicorn app.main:app --reload --port 8000
```
既定の `DATA_SOURCE=yfinance` ならAPIキー不要でそのまま動きます。
Python は **3.9〜3.14** を想定しています（3.8以下は pandas が非対応）。

### 2. フロントエンド起動
```bash
cd frontend
npm install
npm run dev
```
ブラウザで http://localhost:5173 を開いてください。

### 動作確認
```bash
curl http://localhost:8000/api/health
```

## APIエンドポイント

| パス | 説明 |
|---|---|
| `GET /api/health` | 稼働確認。取得元と利用可能な時間軸を返す |
| `GET /api/timeframes` | 各時間軸のパラメータと根拠 |
| `GET /api/watchlist` | ウォッチリストの銘柄一覧 |
| `GET /api/watchlist/full?timeframe=1d&with_backtest=false` | 全銘柄の判定を一括取得 |
| `GET /api/stock/{code}?timeframe=1d` | 個別銘柄の判定＋AI信頼度 |
| `GET /api/screen?timeframe=1d&min_stars=4` | 母集団から★4以上を抽出 |

### スクリーナー
`universe.py` の母集団（日経225中心の246銘柄）をスキャンします。

**★だけでは絞り込めない**（10年検証で★に優位性がないと判明）ため、既定では
**「その銘柄で単純保有を上回っているか」で足切り**し、上回り幅の大きい順に並べます。

```bash
curl "http://localhost:8000/api/screen?min_stars=4&limit=12"
```

実行例（2026-07-26・業種相対強弱を入れた後）：246銘柄中**15銘柄**が通過しました。

| 銘柄 | 業種 | 単純保有との差 |
|---|---|---|
| 7013 IHI | Industrials | +9.36% |
| 4661 オリエンタルランド | Consumer Cyclical | +8.42% |
| 6861 キーエンス | Technology | +6.60% |
| 6326 クボタ | Industrials | +6.57% |
| 4519 中外製薬 | Healthcare | +5.52% |

現在のウォッチリストのA群がこの15銘柄です。

`require_positive_edge=false` を付けると従来どおり★順で返します。

> **注意：** 過去に単純保有を上回った銘柄を選ぶこと自体が過学習になり得ます。
> 全体で優位性がない以上、この6銘柄も「たまたま過去に合っていた」だけの可能性があります。

母集団は**証券コードのみ**で保持しています。社名の手打ち間違いで別銘柄を提示する事故を防ぐため、
銘柄名は抽出できた銘柄についてのみ yfinance から取得します（英語名で返ります）。

## カスタマイズ

| やりたいこと | 編集する場所 |
|---|---|
| ウォッチリストの銘柄 | `backend/app/config.py` の `WATCHLIST`（現在30銘柄） |
| 追加情報のON/OFF | `config.py` の `USE_SECTOR_STRENGTH` / `USE_VOLUME_FEATURE` / `USE_RELATIVE_STRENGTH` |
| 業種データ | `backend/app/sector_cache.json`（`sectors.build()` で再生成） |
| エントリー方式 | `backend/app/config.py` の `ENTRY_MODE`（breakout / market / pullback） |
| 損切りの方式 | `backend/app/config.py` の `STOP_MODE`（atr / pct）と `STOP_ATR_MULTIPLE` |
| 損切り幅（固定%の場合） | `backend/app/config.py` の `STOP_LOSS_PCT_BY_TIMEFRAME` |

## 取得元の差し替え（リアルタイム化）

`app/datasource.py` が取得元を切り替えるハブです。新しい取得元を追加するには：

1. `async def fetch_bars(code: str, tf: TimeframeParams) -> pd.DataFrame`
   （列: `date, open, high, low, close, volume`）を持つモジュールを作る
2. `app/datasource.py` の `_get_provider()` に分岐を1つ足す

`indicators.py` 以降は変更不要です。

リアルタイム性が必要な場合の候補：
- **auカブコム証券 kabuステーションAPI**：口座があれば無料。REST + WebSocket でリアルタイム配信。
  デイトレ用途ならこれが本命です（kabuステーションの常時起動が必要）。
- **楽天証券 RSS**：MarketSpeed II 経由。Excel RTD ベースなので連携に一手間かかります。
